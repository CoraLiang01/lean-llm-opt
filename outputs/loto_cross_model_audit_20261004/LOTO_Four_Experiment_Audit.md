# 四组 LOTO 实验代码与结果审计

审计日期：2026-10-04。结论针对 GPT-4.1 的两个 V1 目录与本次提供的 OSS20b 输出，不混用早先非 V1 成绩。

## 结论

截图中的 OSS20b 结果正确。四组的 LOTO 分组、示例删除和 route 禁用控制对齐，但 GPT-4.1 与 OSS20b 的基础推理/数据/代码流程并不完全相同。相反的总分方向主要对应不同的执行失败恢复和新失败，不能直接解释为模型对未见类型的泛化规律相反。

本次没有修改四份 notebook、原始实验结果或审稿回复，也没有调用模型或执行保存的生成代码。完成了逐题记录核对、代码静态检查及使用模拟模型/求解器的离线控制验证。

## GPT-4.1 增分的具体来源

E2 相对 E1 新增 23 道匹配、丢失 10 道匹配，净增 13；共同匹配 58、共同不匹配 10。这是 V1 的配对数字，不是旧实验的新增 21/丢失 13。

| 新增匹配题在 E1 中的状态 | 数量 |
|---|---:|
| NoneType 模型对象接口失败 | 15 |
| 建模输出截断 | 4 |
| 缺少全局 model 对象 | 1 |
| Gurobi 不支持 keyformat 参数 | 1 |
| 生成模型不可行 | 1 |
| 已求解但目标值错误 | 1 |
| 合计 | 23 |

即 22 道从执行失败恢复，只有 1 道从已求解但目标错误变为匹配。丢失的 10 道中，6 道仍能求解但目标错误，4 道分别因 CSV 行结构、客户列映射、数值解析和 API 超时失败。

E1 的 31 个失败中，19 个是 NoneType，7 个是输出截断，另有 1 个模型对象缺失、2 个 CSV 行结构错误、1 个 Gurobi 参数错误及 1 个不可行模型。19 个 NoneType 全部通过保存代码的语法树/文本检查确认：函数内部创建模型并调用 optimize，但没有 return；外层 m = solve_function(...) 因而得到 None。GPT 执行器随后 with model 报错。

典型代码为：

```python
def solve_problem(...):
    m = gp.Model(...)
    # 添加变量、约束、目标
    m.optimize()
    # 缺少 return m

m = solve_problem(...)
```

这些 19 题中并不存在另一个可直接回收的有效全局模型，所以仅将模型查找替换为 namespace.get('m') or namespace.get('model') 不能修复。OR-043 则定义了返回模型的函数，却未调用。须统一生成程序的模型返回接口并重新执行评估，不能静态追认这些题已求解或目标正确。

RA 从 10 道匹配增至 21 道，贡献净增 13 道中的 11 道。在两实验均成功求解的同一组 66 题中，匹配数反而为 E1 64、E2 59。此子集是按实验后结果选择的描述性诊断，不是无偏的建模能力或因果效应估计。

## OSS20b 减分的具体来源

E2 相对 E1 新增 5 道匹配、丢失 8 道，净减 3；共同匹配 80、共同不匹配 8。

新增 5 道：3 道从执行失败恢复（OR-009、OR-062、OR-076）；2 道从已求解但错误恢复（OR-039、OR-040）。后两题 E1 遗漏产品重量相关约束，E2 的 Others 流程恢复相关约束后匹配参考目标。

丢失 8 道包括 5 个失败和 3 个目标值错误：

| 问题 | E2 的结果/机制 |
|---|---|
| OR-005 | 分类阶段 Ollama 500 / CUDA illegal memory access，尚未选出 route |
| OR-007 | TP 留出轮仍预测 TP，被 DisabledRouteError 阻止 |
| OR-057 | RA 留出轮仍预测 RA，被 DisabledRouteError 阻止 |
| OR-059 | 生成程序对字符串调用 astype，引发 AttributeError |
| OR-072 | 转入 RA 后执行失败，KeyError: 1 |
| OR-041 | 变量取值域改变；E1 整数、E2 连续，目标由 3912 变为 4408.523076923077；题面未明确整数，宜称与基准的取值域假设不一致 |
| OR-087 | 不同参数读取同一行值，price 与 cost 相同且有正固定成本，返回目标 0 而非参考 6243055.96 |
| OR-082 | 构建距离矩阵时反复用每条记录覆盖所有条目，最终保留末条记录，目标 231 而非参考 199 |

2 个违规分类均被拦截，禁止 route 没有实际执行。这是模型未遵守可用标签提示而导致的真实协议失败，不是禁用逻辑失效。OR-005 没有类别输出，不能计为禁用类别选择。三题均在 E1 匹配；其余新增/丢失在数量上各为 5，不应由此推断重跑这三题一定正确，也不应擅自剔除后改分。

在两实验均成功求解的同一组 88 题中，E1 匹配 83、E2 匹配 82。3 题总体差异不足以从单次运行建立模型能力方面的稳定方向性结论。

## 对齐与未对齐的代码

四组均按相同 101 个唯一题号和七类分组；清单中的参考库 SHA-256、删除的原始示例、保留数量及评分容差一致。四份公共 fold 控制和 runner 代码一致；对应两个 full baseline 的当前 SHA-256 与 notebook 声明一致。

每次只删除该语义 Type；Mixture/Others 独立删除，但映射至同一 Others 执行 route，故 E2 留出其中任一类都会禁用两个标签。提示词中的固定类别定义及手写示例保留。不能称作彻底移除模型关于该类别的一切知识。

| 实现点 | GPT-4.1 | OSS20b |
|---|---|---|
| NRM CSV 模式 | planned | planned |
| RA/TP/AP/FLP CSV 模式 | legacy | planned |
| 五个具体 route 的代码指导 | 从过滤后的参考 CSV 检索 Code 示例 | 固定 CSV_CODE_GUIDANCE；没有同样的 Code 示例检索 |
| Others 示例 | 使用过滤后的参考库 | 使用过滤后的参考库 |
| 模型对象查找 | 固定全局 m 或 model | 另可查找唯一全局 gp.Model |
| 分类适配 | GPT ReAct 及一次 FileQA 调用约定 | 容错 parser、补全与纠错提示；E2 同时传递允许标签 |
| 执行适配 | 基线原有执行方式 | 额外数据清理、代码规范化及求解器参数 |

因此可以称两模型使用对齐的 LOTO 干预定义，但不能声称完整 pipeline 相同、仅换了模型。尤其“删除示例会同样删除两模型各阶段的代码示例”不准确：OSS 五个具体 route 的固定代码指导仍在。

- OSS 使用本次提供的逐题 CSV、报告、清单与案例文件重新核验。模型名为 gpt-oss:20b，但未提供服务端权重摘要和完整运行环境快照。
- 保存的 source_fingerprint 包含数据/路径等；当前无法独立重建历史运行完整指纹，不能声称已证明历史运行字节级源码等于当前 notebook。

- 当前 GPT 两份缺少 OSS 末尾的完整保存结果矩阵报告单元，且运行开关/说明不一致，属于维护问题；没有证据表明其改变已保存分数。

## 最终结果应如何使用

现有分数可以作为当前实现的历史运行结果；不能据此宣称 GPT-4.1 去掉专用 route 后建模能力更强、OSS20b 的类型泛化更弱，或 OSS20b 在相同完整流程下优于 GPT-4.1。

若要形成排除已知实现影响的最终对照，应先统一模型返回接口/验证规则，再对比较的两个条件采用相同修复和重跑规则。服务故障、非法标签、输出截断、建模错误应分别报告。若采用非法标签补问、基础设施重试或模型对象恢复，须事先固定规则并在所有相关条件一致执行，保存为新版本结果而非覆盖 V1。仅修复或重跑某一条件后与另一条件旧结果比较会引入额外差异。
