## Full-model changes

The original CSVQA loading/profile/planning/Python extraction is reused rather than replaced. The tool is invoked once by Python before one mathematical-model call. Demonstrations can no longer cause the modeling agent to skip reading the current data. Illustrative phrases cannot justify data exclusion; categorical code families use prefixes, with arbitrary text retaining its declared predicate semantics. The validator preserves field values and axis order, checks unique complete identifiers, and optionally exposes a numeric-suffix bijection only when it is complete and nonidentity. It never invents a city/customer association or aligns unrelated axes by a reference answer.

Shared model-return and Gurobi constraints remain available even when a reference-example pool is empty. Actual interface failures motivated guidance on supported keyword arguments, flattened composite keys, identifier types, logical constraints, and returning one live optimized model. The original bulk-variable-name clearing remains. The Others without CSV modeling function and its reference source are unchanged apart from disabling parser correction; its API performance was not tested because every supplied 101 case has external CSV inputs.

There is no planner repair, generated-code edit loop, truncation regeneration or solver rerun. The original SDK maximum of two HTTP transport retries is retained and actual retry events are logged separately. Every method uses GPT-4.1's fixed 2025-04-14 snapshot, the same embedding-model name, temperature 0, top_p 1, Gurobi Threads=2, MIPGap=1e-4 and Objective Match rel_tol=abs_tol=1e-4. A common external 1,800-second case deadline interrupts unfinished execution; no feasible incumbent is substituted for an optimal returned result.

## Ablation boundaries

Both ablations validate and reuse all 101 final full-model classification predictions. They never reclassify after removing a component. The effective retrieved reference corpus is `Large_Scale_Or_Files/RAG_Examples_All.csv`, with 15 rows: Mixture 8, Others 2 and one each for AP, FLP (stored as UFLP), NRM, RA and TP. `rag_only_removed_example_candidates.json` lists every row index, type and prompt whose model/Observation/code demonstrations are removed. The separate query-only fixed INTEGER, MULTI-PERIOD FLOW and LOGIC+BINARY examples are removed too. Classification FileQA definitions, CSVQA profiles, declarative plans, Python extraction/validation and logged full-source fallback remain; query-only ORLM_QA retrieval remains. Removal of inserted few-shot examples does not remove the tool's retrieval functionality.

Few-shot Only uses `pandas.read_csv(dtype=str, keep_default_na=False)` to serialize all original fields and rows as the current Observation. It performs no LLM extraction, selection, numerical rewrite or summary. The entire Observation reaches mathematical modeling. Code generation receives the original query, source paths/column names and symbolic variable/objective/constraint sections. Python excludes parameter/Data Mapping sections and markdown tables from the generated model at this transfer boundary; it does not modify the stored complete Observation or replace source coefficients. Code reads the original files at runtime. Offline audits cover the prior 100 saved mathematical models and both canonical/Other transfer paths.

The initial complete Few-shot Only v4 pass scored 80/101, but some generated mathematical models echoed complete coefficient tables into code generation. That round is preserved as preliminary and fails the strict transfer boundary. The v5 complete pass is the final comparison, regardless of whether its score is better or worse; this is not best-of-round selection. See `few_shot_v5_adoption.json`.

## LOTO boundaries

The baseline's effective classification reference is RAG_Examples_All rather than the unused RefData file name. Each fold removes its target semantic type before mapping Mixture/Others to the Others workflow; UFLP is normalized to FLP. Classification is recomputed from the original question, remaining references and generic definitions. Target-type fixed classification examples are also removed. The separate query-only reference library is filtered by its original problem-type field, and target-type fixed query-only triggers are removed. All exclusions and guards are tested offline. The separate library contains 3 Knapsack Problem rows, which are normalized to RA; an RA fold therefore removes 20 of its 79 rows, and an Others fold removes 13. This final query-only alias correction changes only one unused filter function per LOTO notebook. Their other definitions match the evaluated frozen copies; all 101 measured cases have CSV inputs. The corrected query-only filter is verified offline but has not been API-evaluated. Both hashes and the scoped difference are recorded in delivery_control.json.

Examples Only allows the original workflow even if its example pool is empty. Examples And Route excludes every semantic label that maps to the disabled workflow, including both Mixture and Others when that workflow is disabled. The route guard executes before mathematical modeling. The true type is used for fold grouping/reference exclusion and scoring; no reference objective/model or true type is used to choose a replacement route. Each attempted case stores its fold manifest with removed reference indices/prompts and remaining counts.

## Switches, history and reproduction

The full notebook's 606 switch was enabled only after 101, Variants and all nine sheets completed and the necessary gate passed. It requests all 101 questions through every one of the six workflows, with no reuse of automatic model results. It has not been executed in this task. `delivery_control.json` records the evaluated/delivered hashes and the two changed control cells; model definitions are identical to `full_v4/frozen_notebook.ipynb`.

For reviewed existing results, read `report/REPORT.md`, `report/metrics.csv`, `report/all_case_results.csv` and `report/failures.csv`. The reproducible runner freezes each notebook and records all data hashes/settings. Its commands are in the report. Running those same commands resumes recorded successes and failures without further inference; no failed case is reattempted. For a new round, choose a new result version/directory and retain the entire previous round. Do not overwrite the frozen notebook or prior attempt records. Notebook switches are intended for an explicitly selected fresh output directory; the delivered experiment switches are off except the reviewed 606 control.

All untested changes or unresolved semantic conventions are marked in the report. A single final pass cannot establish repeat-run stability. Missing CSVQA traces after API/model-output failures are marked unavailable rather than fabricated; fallback totals are lower bounds when such records exist.
