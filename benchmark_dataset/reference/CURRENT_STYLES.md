# 当前十二题的表达与输入形式

本次调整改变了数据表示和题目表达，保留所有业务约束、有效经济参数和最优值。原版本位于 benchmark_archive/before_style_diversification。

| 题目 | 输入与主要阅读方式 | 文件数 |
| --- | --- | ---: |
| AP1 | 建筑项目派工；人员表、项目表、成本矩阵 | 3 |
| AP2 | 服务任务报价；逐行列出人员、任务和报价，未列出的组合不可选 | 3 |
| AP3 | 工作包排班；成本矩阵分在三个文件，用人员编号关联 | 5 |
| RA12 | 生鲜订货；当前物品表直接给单位收益及固定费用 | 9 |
| RA1 | 面包店备货；当前物品表直接给收益及费用，保留资源单位换算 | 9 |
| RA2 | 车辆库存核对；截至 2026-03-12 的版本记录，所有金额已是美分 | 24 |
| RA3 | 车辆报价选购；当前有效数据、直接收益及费用，资源单位已统一 | 9 |
| RA4 | 挪威车行多币种采购；保留截至 2026-05-07 的版本记录与汇率 | 25 |
| RA7 | 纽约开发模块选择；当前收益分量相加，资源单位已统一 | 13 |
| RA10 | 超市展示区配货；当前表，跨文件关联商品与分区，独立分区容量 | 13 |
| RA13 | 游戏版本与平台配置；当前表，保留币种换算及独立平台内存 | 12 |
| RA14 | 空调分仓储区摆放；直接收益及费用，容量单位已统一 | 11 |

只有 RA2、RA4 需要事件版本筛选。其余七道 RA 的输入没有日期、revision、DELETE 或业务主体过滤要求，直接使用当前表。只有 RA4、RA13 需要汇率换算。统一金额题均保留美分作为输出单位，以保证与已有 label 对齐。

RA1/RA3/RA12/RA14 将每单位收益合计为 unit_benefit_cents，并把每种物品固定费写为 item_fee_cents。RA2/RA7/RA10 保留带正负号的 amount_cents 分量。RA3/RA7/RA14 的资源用量已与容量转换到一致的基础单位。

所有题目仍有授权、整数批量、类别上下限、资源容量及适用的互斥/依赖/组合奖励约束。此次简化主要针对数据读取，不是删除优化约束。没有改变任何一题的最优值。

## 使用

将整个 benchmark_dataset 目录替换到运行工程中，同时替换 Test_Dataset/Large-scale-or/Large-scale-or-101_冗余列35个 copy.csv。不要只覆盖新文件而保留旧 inputs：本次各题文件数量及地址已变化。按问题 CSV 的 Dataset_address 精确读取输入文件，reference 下的参考答案不属于输入。

在已配置环境的项目根目录，可运行 `uv run python benchmark_dataset/reference/validate.py` 做本地验证。该验证从当前文件重新构建模型，AP 另外以独立最小费用流交叉验证，RA 审核约束与目标值，且全部 LP 重载求解结果一致。所有十二个 label 保持不变。未调用模型 API，尚不能判断新风格的 agent 通过率。

reference 下此前的 agent 诊断报告描述的是历史输入版本，不能直接视作当前版本的模型测试成绩。
